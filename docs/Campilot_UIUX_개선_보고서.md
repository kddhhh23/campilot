# Campilot UI/UX 개선 보고서

> 후속 변경: 첫 화면과 시간 선택을 분리한 최신 흐름은 [장소·시간 선택 수정 보고서](Campilot_장소_시간_선택_수정_보고서.md)를 참고하세요. 아래 내용은 최초 디자인 개선 시점의 기록입니다.

작성: 2026-11-14

## 무엇을 바꿨나

첫 사용자가 장소를 선택하고 다음 행동을 찾기 쉽도록 화면을 재구성했다. 기존의 긴 개발용 설명과 수치 중심 화면을 장소 선택, 전력 판단, 이동, 차박, 귀가 단계로 정리했다.

| 이전 | 개선 |
|---|---|
| SDK 연결 정보가 첫 화면의 대부분을 차지 | 연결 정보는 상단 버튼의 상세 대화상자로 이동 |
| 캠핑장을 긴 세로 목록으로 표시 | 넓은 화면에서 그림과 함께 세 곳 비교, 좁은 화면에서는 세로 배치 |
| 각 영역에 버튼이 반복되고 다음 버튼이 아래로 밀림 | 화면 하단에 다음 행동 고정 |
| 계산식과 kWh 수치를 모두 먼저 표시 | 충전 필요 여부와 추가 충전량을 먼저, 계산식은 상세 |
| 설정 입력 여러 개를 동시에 요구 | 체류 시간부터 설정, 온도·고급 설정은 펼쳐서 확인 |
| 시연/SDK 등 개발자 용어가 본문에 반복 | 시연 모드/차량 연결처럼 사용자 언어로 표현 |
| 초기화 버튼을 누르면 즉시 여정 삭제 | 여정 종료 전 확인 대화상자 |
| 오류와 예외 설명이 상세에만 남을 수 있음 | 경로 실패와 오래된 정보는 현재 화면에서 안내 |

## 적용한 스킬

이미 설치되어 있던 아래 스킬을 읽고 적용했다. 온라인 원본 저장소도 확인했으며, 중복 설치나 추가 패키지 설치는 하지 않았다.

- [Anthropic Frontend Design](https://github.com/anthropics/skills/tree/main/skills/frontend-design): 제품에 맞는 시각 방향, 글자 계층, 사용자 중심 문구, 화면 직접 검토.
- [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill): 대비, 터치 영역, 중요한 행동, 점진적 정보 공개, 명시적 오류 상태.
- writing-plans: 구현 순서와 검증 범위를 문서화.

UI/UX Pro Max의 디자인 시스템 검색은 웹 랜딩 페이지/영문 글꼴 권고도 포함했다. 해당 부분은 한글 차량 앱에 맞지 않아 채택하지 않았다. 스택 검색은 현재 Compose 구조에 해당하는 항목만 검토했고, 필요 없는 내비게이션 구조 변경은 하지 않았다.

## 디자인 시스템

- 밝은 안개색 배경, 짙은 숲색 버튼, 흰색 표면.
- 밤 화면은 짙은 녹색 바탕과 밝은 민트색 강조.
- 한글 가독성을 위해 Android 기본 sans-serif 유지. 제목 38sp, 본문 20sp, 보조 16sp, 주요 버튼 20sp.
- 주요 버튼 최소 높이 64dp. 온도 조절은 60dp.
- 숲·호수·산 풍경을 Compose Canvas 벡터로 표현. 실제 캠핑장 사진으로 오인하지 않도록 시연 장소를 명시.
- 주요 동작은 화면 하단 고정. 900dp 이상이며 글꼴 배율이 작은 경우 캠핑장 3열, 그 외는 세로 배치.
- 자동 재생 애니메이션 없음. 색 이외에도 선택 문구와 RadioButton 의미 정보를 제공.

대표 색상 대비를 계산했다: 낮 버튼 7.74:1, 낮 보조 본문 5.28:1, 낮 기본 본문 13.19:1, 밤 보조 본문 8.01:1, 밤 버튼 7.70:1.

## 화면 흐름

1. 첫 화면에서 체류 시간과 배터리를 확인하고 장소 선택.
2. 하단 ‘전력 계획 확인’으로 충전 필요 여부 확인.
3. 바로 출발 또는 충전소 경유 출발.
4. 충전소 도착 → 목표까지 충전 시연 → 캠핑장으로 출발.
5. ‘차박 시작’ 후 배터리·남은 시간·설정 온도 확인.
6. 시연 모드의 자동 관리 켜기/끄기. 과소비 시연은 ‘시연 도구’ 안에 배치.
7. 하단 ‘귀가 시작’ → ‘귀가 완료’.

차량 모드에서는 실제 SDK 연결과 권한·주차·최신 값 제약을 유지한다. 실제 공조 작동의 지원 제한과 실측 전력 모델 미구현 범위는 기존 SDK 보고서와 같다.

## 변경 파일

- MainActivity.kt: 간결한 상단 메뉴, 차량 연결 상세, 테마 전환.
- ui/CampilotDesign.kt: 색상·글자·버튼·상세 펼치기·풍경·배터리 표시.
- ui/PlanEditor.kt: 체류 시간 중심 설정 화면.
- ui/JourneyScreen.kt: 단계별 화면과 고정 주 행동.
- ui/CampilotViewModel.kt: 경로 실패 여부를 별도 상태로 노출. SDK 호출/에너지 계산 정책 유지.

## 리뷰와 검증

첫 사용성 테스트는 기존 화면에서 실패한 뒤 개선 화면에서 통과했다. 독립 코드 리뷰에서 발견한 다음 세 문제도 회귀 테스트를 먼저 실패로 확인했다.

1. 차량 모드의 숨겨진 시작 온도가 유효한 온도 범위 저장을 막음.
2. 오래된 배터리로 충전 완료/차박 종료 예상 값을 표시함.
3. 영문 SDK 경로 오류가 한국어 키워드 검사에 잡히지 않아 숨겨짐.

차량 모드에서 쓰지 않는 계획 시작 온도는 허용 범위로 정규화했다. 최신 값이 없으면 예상치를 표시하지 않는다. 경로 실패는 번역된 문구 검사 대신 명시적 상태로 표시한다.

최종 전체 검증: gradle-run 0004, 종료 코드 0.

- 단위 테스트 19/19, 계측 테스트 26/26 통과. 건너뜀 없음.
- lintDebug 성공. 경고 없는 빌드라는 의미는 아님.
- 375dp 너비/글꼴 배율 1.5에서 차박 주요 행동과 종료 확인 접근성 검증.
- 실제 Pleos 에뮬레이터의 넓은 화면에서 낮/밤 테마와 풍경 경계를 직접 확인.
- FirstUseTest 2개: 기존 화면 RED(0001) → 개선 후 GREEN(0002).
- DesignStateTest 3개: 리뷰 결함 RED(0003) → 수정 후 전체 GREEN(0004).

- 실제 사용성 실험, 모든 Android 화면 크기 및 최대 글꼴 배율 전체를 검증한 것은 아님.

## 범위

실제 사용자 대상 사용성 실험이나 실차 인증을 수행한 것은 아니다. 에뮬레이터 화면 확인과 자동 UI 테스트로 검증한 프로토타입이다. 새로운 SDK 기능이나 실제 캠핑장 데이터는 이번 디자인 변경에 포함하지 않는다.
