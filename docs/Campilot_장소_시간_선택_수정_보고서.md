# Campilot 장소·시간 선택 수정 보고서

작성: 2026-11-14

## 변경한 사용자 흐름

1. 첫 화면에서 현재 위치와 추천 차박지 3곳을 확인한다.
2. 장소 카드를 고르고 하단 **출발 시간 정하기**를 누른다.
3. 다음 화면에서 현재 시각과 내일 날짜를 확인한다.
4. 내일 차박지에서 집으로 출발할 시간을 정한다. 기본 09:00, 09/10/11시 빠른 선택과 24시간제 직접 선택을 제공한다.
5. **전력 계획 확인**을 누르면 기존 전력 화면으로 이동한다.

첫 화면에서 배터리·체류 시간·계획 변경 항목을 제거했다. 고급 설정은 상단 차량 연결/시연 모드의 상세 대화상자 안으로 이동했다. 출발 시간 화면에는 전력·공조 입력을 넣지 않았다.

장소를 다시 고르거나 전력 화면에서 출발 시간을 수정할 수 있다. Activity 재생성 및 화면 간 뒤로 이동에도 선택한 장소와 시각이 유지된다. 앱 프로세스가 종료된 뒤 여정 복원은 이번 범위에 포함하지 않았다.

## 위치와 시간의 의미

- 위치·장소·거리는 기존에 승인된 목업 데이터다. 출발지는 **서울시청 인근**, 추천은 솔숲/호수/별빛 캠핑장 3곳이다.
- 화면에 **현재 위치 · 시연**과 시연 장소 안내를 표시한다. GPS 조회나 실제 주변 검색을 추가한 것은 아니다.
- 현재 시각은 목업이 아닌 기기 현지 시각이다. 화면이 활성화된 동안 갱신하며, 백그라운드에서는 갱신 작업을 중단한다.
- 선택 시각은 집 도착 시간이 아닌 **차박지에서 집으로 출발할 시간**이다.
- 편집 중 날짜가 바뀌면 ‘내일’ 날짜도 새 현지 날짜의 다음 날로 계산한다.
- 전력 계획에는 현재부터 내일 출발까지의 기간을 반영한다. 도착 예상 시각이 없는 목업이므로 이동 시간이 포함된 보수적인 사용 기간이며, 실제 체류 시간과 다를 수 있음을 전력 상세에 설명했다.

## 구현

새 SDK나 라이브러리는 추가하지 않았다. 기존 공식 Pleos Vehicle 2.3.2 / NaviHelper 3.0.5 연결을 유지한다.

- domain/DepartureSchedule.kt: java.time으로 다음 날 날짜와 출발 시각, 사용 기간 계산.
- domain/Journey.kt: SCHEDULE 단계 및 시연 출발지 추가.
- ui/CampilotViewModel.kt: 시각 선택과 현재 시계 상태 관리, 화면 활성화에 따른 갱신 시작/취소, 확인 시 CampPlan.hours 반영.
- ui/DepartureScreen.kt: 현재 시각과 출발 시각을 분리한 화면. 넓은 화면은 나란히, 좁은 화면은 세로 스크롤.
- ui/JourneyScreen.kt: 장소 추천에 집중한 첫 화면 및 시간 수정 진입.
- MainActivity.kt: 뒤로 가기와 고급 설정 위치 변경.

화면은 상태와 이벤트 콜백을 받고, Android 시간 선택창은 화면 수명에 맞춰 해제한다. 장소·시간 선택 자체로 길 안내나 차량 공조 명령을 보내지 않는다.

확인한 사례:
- 새 첫 화면/시간 단계 테스트 2개가 변경 전 실패하고 변경 후 통과.
- 다음 날 계산, 월말·연말, 00:00 및 임의의 분 단위 선택.
- 자정 0.5초 전의 양수 기간 계산: 독립 리뷰에서 지적된 초 절삭 문제를 실패 테스트로 재현 후 수정.
- 장소/시각 선택 후 Activity 재생성, 장소로 돌아가기, 전력 화면에서 시간 수정.
- 출발 시각을 1시간 늦추면 계획 기간이 약 1시간, 1.2kW 목업 예산이 약 1.2kWh 늘어남. 시간 선택만으로 내비 요청 없음.
- 375dp·글꼴 1.5배에서 시간 선택 및 하단 버튼 접근.
- 기존 SDK/충전/차박/귀가 회귀 테스트.
- Pleos 에뮬레이터에서 두 화면 직접 확인 및 기본 시간 선택창으로 **08:45 입력·반영** 확인.

독립 코드 리뷰 1회 후 발견된 자정 경계 문제를 수정하고 전체 테스트를 다시 실행했다. 실제 GPS·실차 제어 정책·프로세스 종료 후 복원은 이번 화면 변경의 검증 범위 밖이다.
