# Campilot — 차박 비서 앱 기획안 v1.0

## 1. 서비스 개요

**Campilot은 다음 이동에 필요한 배터리를 고려해 차박지를 추천하고, 체류 중 공조와 에너지 사용을 관리하는 차량용 비서 앱이다.**

주요 대상은 전기차로 차박을 준비하는 사용자다. 특히 “현재 배터리로 어디까지 가고, 얼마나 머물 수 있는지” 판단하기 어려운 초보 차박 사용자의 문제에 집중한다.

핵심 사용자 질문은 다음 세 가지다.

- 지금 배터리로 이 캠핑장에서 차박해도 될까?
- 밤새 공조를 사용하려면 미리 얼마나 충전해야 할까?
- 예상보다 배터리가 빨리 줄어들면 무엇을 바꿔야 할까?

서비스의 차별점은 **목적지 추천·전력 계산·공조 제어·모니터링이 동일한 에너지 계획을 공유한다는 점**이다.

**확정한 범위:** 캠핑장 중심 추천, 전력 예산에 연동한 공조 자동 제어, 기획서와 핵심 시연 제출. 1차 전력 계산은 이동·차량 기본 소비·공조를 대상으로 하며, V2L 외부 기기는 후속 확장으로 둔다.

## 2. 핵심 기능과 사용자 흐름

| 기능 | 주요 동작 | 사용자에게 보여줄 결과 |
|---|---|---|
| 위치 기반 목적지 추천 | 현재 위치 주변 캠핑장을 찾고, 이동 거리와 차박 후 전력 여유를 함께 비교 | 추천 이유, 거리, 시설, 충전 필요 여부 |
| 예상 전력 계산 | 현재 배터리, 이동 거리, 체류 시간, 공조 사용 조건, 다음 목적지를 바탕으로 필요한 에너지 계산 | 도착·차박 종료 예상 잔량, 부족한 에너지, 권장 출발 충전량 |
| 차량 공조 자동 제어 | 사용자가 허용한 온도 범위 안에서 에너지 예산에 맞춰 공조 설정 조절 | 현재 설정, 변경 이유, 자동 제어 중지 버튼 |
| 에너지 모니터링 및 관리 | 현재 잔량과 소비 추세를 계획과 비교하고 남은 시간을 기준으로 재계산 | 예상 종료 잔량, 계획 대비 차이, 조치 제안 |

화면은 다음 네 단계로 구성한다.

**① 차박 계획:** 체류 시간, 다음 이동 목적지, 선호 온도와 허용 범위를 입력한다. 예비 배터리는 기본 10%로 제안하되 사용자가 변경할 수 있다. 이는 제품 초기값이며 안전을 보장하는 기준은 아니다.

**② 캠핑장 비교:** 이용 조건이 맞는 캠핑장을 대상으로 ‘현재 계획을 충족하는지’를 먼저 보여주고, 같은 조건에서는 가까운 순서로 정렬한다. 캠핑장 등록 사실과 차량 숙박 허용 여부를 구분하고, 이용 조건의 출처·확인일을 표시한다.

**③ 전력 계획 확인:** 이동·차박·다음 이동·예비분을 나누어 표시한다. 부족하면 추가 충전, 가까운 목적지, 체류 시간 단축 중 가능한 대안을 제시한다.

**④ 차박 대시보드:** 현재 잔량, 예상 종료 잔량, 공조 설정을 중심으로 보여준다. 자동 제어는 사용자가 차박 시작 시 켜며, 직접 공조를 변경하면 앱의 자동 제어를 일시 중지한다.

## 3. 전력 계산과 차량 연동 설계

**전력 계산의 기본 구조**

> 필요한 에너지 = 캠핑장까지 이동 + 차박 중 소비 + 다음 목적지까지 이동 + 예비 에너지  
> 추가 충전 필요량 = 필요한 에너지 − 현재 사용 가능한 에너지  
> 단, 결과가 음수이면 추가 충전 필요량은 0으로 표시한다.

- 이동 에너지는 경로 거리와 전비를 사용한다.
- 차박 에너지는 체류 시간과 공조·기본 전장 소비의 평균 전력을 사용한다. 평균 전력에 기본 소비가 포함됐다면 중복 합산하지 않는다.
- 배터리 잔량을 kWh로 환산하려면 사용 가능 배터리 용량이 필요하다. 확인되지 않은 차량은 임의로 용량을 추정하지 않고 입력 또는 검증된 차량 프로필을 요구한다.
- 도착 이후에는 현재 잔량을 기준으로 **남은 체류와 다음 이동**만 재계산한다.
- 예상치는 범위로 표시하고, 충전 필요 여부는 소비가 큰 쪽을 기준으로 판단한다. 이동 중 어느 구간에서든 에너지가 부족한지도 별도로 확인한다.
- 필수 데이터가 없으면 ‘충전 불필요’ 대신 ‘계산에 필요한 정보 부족’을 표시한다.

**공조 제어 원칙**

전력 부족이 예상되면 난방은 설정 온도를 낮추고, 냉방은 높이는 방향으로 사용자가 정한 범위 안에서 조절한다. 범위 끝에서도 예산을 충족하지 못하면 체류 단축이나 충전을 제안한다. 공조를 임의로 끄거나 허용 범위를 넘지 않는다.

공조 변경 요청 후에는 적용 결과를 확인하고, 실패한 요청을 성공으로 표시하지 않는다. 주행 전환·차량 연결 끊김·오래된 데이터·권한 부족 시 새로운 자동 제어를 중단한다. 앱 재실행 시에는 상태를 확인한 뒤 사용자에게 재개를 요청한다.

**연동 구조**

차량 데이터 제공부, 전력 계산부, 공조 제어부를 분리한다. 모의 데이터와 Pleos 데이터를 교체해도 같은 계산·화면을 사용하도록 한다. 데이터에는 측정 시각과 실제값·입력값·시연값 구분을 포함한다.

| 연동 대상 | 활용 계획 |
|---|---|
| Vehicle SDK | 배터리 잔량·전비 조회, 공조 상태 조회와 설정 |
| FusedLocation SDK | 현재 위치 확인 |
| NaviHelper SDK | 선택한 목적지·경유지의 내비게이션 연동 |
| 캠핑장·경로·기상 데이터 | 실제 서비스 단계에서 출처와 사용 조건이 확인된 데이터 연결 |

SDK 문서에서 배터리와 공조 기능을 확인했지만, 실제 사용 가능 여부는 차량별 지원 기능과 승인된 권한에 따라 판단해야 한다. [Vehicle SDK](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro), [API 사용 정책](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/)

밤새 자동 관리가 가능한지는 차량의 전원 상태와 앱 실행 조건까지 검증해야 한다. **1차 시연은 앱이 실행 중인 상황으로 한정**하고, 장시간·백그라운드 동작은 2차 검증 항목으로 둔다. [Pleos 앱 동작 모델](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model)

## 4. 1차 구현 범위와 검증

**1차는 전력 계산과 모니터링이 실제 동작하는 시연용 앱을 만든다.** 캠핑장 추천과 공조 제어는 모의 데이터로 연결한다. 실제 차량 연동 완료로 표현하지 않는다.

| 구분 | 1차 제출 범위 |
|---|---|
| 캠핑장 추천 | 위치·거리·시설이 다른 가상 캠핑장 3곳 비교 |
| 전력 계산 | 입력 변경에 따른 예상 잔량·충전 필요량 계산 |
| 에너지 관리 | 시간과 소비량 변화에 따른 예측 갱신·부족 알림 |
| 공조 자동 제어 | 허용 범위 안에서 변경할 설정과 변경 이유를 모의 시연 |
| 제외 | 실시간 예약, 결제, 회원가입, V2L 기기 관리, 실차 장시간 제어 |

시연에는 가상 차량의 배터리 용량·전비·평균 소비전력을 명시하고, 모든 화면에 시연 모드임을 표시한다. 온도 변경에 따른 소비 감소는 시나리오 가정이며 검증된 절감률로 홍보하지 않는다.

**권장 시연 흐름: 약 90초**

1. 체류 시간과 다음 목적지를 입력한다.
2. 캠핑장별 전력 여유를 비교하고 한 곳을 선택한다.
3. 차박 중 예상보다 소비가 커지는 상황을 재현한다.
4. 앱이 예상 배터리 부족을 알리고 허용 범위 안에서 공조 설정을 조절한다.
5. 변경된 예상 잔량과, 여전히 부족할 때의 대안을 보여준다.

**완료 기준**

- 체류 시간이 길거나 소비전력이 커지면 예상 잔량이 감소한다.
- 계산값이 예비분 경계에 걸리는 경우에도 충전 필요 여부가 일관된다.
- 도착 후 이동 에너지를 다시 차감하지 않는다.
- 자동 제어는 허용 온도 범위를 넘지 않으며 중지 후 추가 변경을 하지 않는다.
- 데이터 누락·연결 실패를 정상 상태와 구분한다.
- 동일 시나리오를 반복해 같은 결과를 재현할 수 있다.

실제 배터리 예측 정확도와 공조 절감 효과는 후속 실측으로 평가한다. 1차 검증은 계산의 일관성과 사용 흐름을 대상으로 한다.

## 5. 공모전 전략과 제출 일정

**발표의 중심 문장**

> “Campilot은 차박 장소를 고르는 순간부터 다음 이동까지, 차량의 에너지를 하나의 계획으로 관리합니다.”

공식 심사 기준은 차량 특화성·창의성·기술 활용성·사업성이며, 개발 산출물에 가산점을 부여한다. 아래 내용을 기획서와 시연에서 각각 증명한다. [공식 심사 기준](https://appdevchallenge.auto-hmg.io/guide/judging-awards)

| 평가 항목 | 강조할 근거 |
|---|---|
| 차량 특화성 | 차량 배터리 상태와 공조 제어가 서비스의 핵심 판단에 직접 연결됨 |
| 창의성 | 다음 이동에 남길 에너지를 목적지 추천부터 체류 관리까지 공통 기준으로 사용 |
| 기술 활용성 | SDK별 역할, 실제 연동 범위, 모의 시연 범위를 구체적으로 구분 |
| 사업성 | 전기차 차박 사용자로 초기 고객을 좁히고, 실제 차박 때 반복 사용하는 흐름 제시 |

사업 모델은 **기본 계획·모니터링 무료, 향후 캠핑장 예약 제휴 수수료**를 초기 가설로 둔다. 제휴 여부가 에너지 적합성 판단을 바꾸지 않도록 한다. 캠핑 커뮤니티와 협력 캠핑장을 초기 유입 경로로 검토하고, 계획 완료율·차박 세션 시작률·다음 차박 재사용률을 측정한다. 시장 규모나 절감률은 근거 없이 수치화하지 않는다.

추가 기능으로는 **사용 후 실제 소비량을 다음 예측에 반영하는 개인화**를 우선 추천한다. 기존 네 기능의 정확도를 높일 수 있어 후속 발전 방향으로 설명하기 좋다.

| 일정 | 목표 산출물 |
|---|---|
| 11월 11일 | 기획 내용·계산 기준·시연 시나리오 확정 |
| 11월 12일 | 전력 계산과 계획 화면 |
| 11월 13일 | 모니터링 및 공조 변경 모의 시연 연결 |
| 11월 14일 | 검증, 시연 영상 녹화, 공식 접수양식 작성 |
| 11월 15일 | 제출 자료 최종 확인 및 접수 |

기획서는 공식 접수양식에 옮기고 시연 영상을 함께 준비한다. 저장소를 제출할 경우 소스와 실행 가능한 APK, 실행 방법을 포함한다. 1차 통과 시에는 12월 3~4일 PT 전까지 실제 동작 앱으로 발전시킨다. [제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission), [공식 일정](https://appdevchallenge.auto-hmg.io/guide/schedule)

개발 인원·경험·가용 시간은 아직 확인되지 않았으므로 위 일정은 **최소 시연 범위를 기준으로 한 작업 순서**다. 초기 대상은 전기차로 가정하며, 내연기관·하이브리드 지원은 이번 범위에 포함하지 않는다.
